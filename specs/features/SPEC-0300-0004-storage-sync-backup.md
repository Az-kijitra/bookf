## 1. ファイルの配置

| ファイル | 場所 |
|---|---|
| データベース（既定） | `%APPDATA%\dev.bookf.app\books.db` |
| 表紙 | データベースと同じフォルダーの `covers\` |
| 自動バックアップ | データベースと同じフォルダーの `books_backup.json` |
| 設定 | `%APPDATA%\dev.bookf.app\settings.json`（`db_path` だけを持つ。壊れていたら既定値で動く） |

データベース・表紙・バックアップが 1 つのフォルダーにまとまるので、フォルダーごと同期・コピーすればよい。

## 2. 同期フォルダーとの併用

- SQLite のジャーナルは `DELETE` モードにする。WAL の `-wal`・`-shm` ファイルが残らず、同期クライアントが書きかけのファイルを拾わない。
- `busy_timeout` は 5 秒。
- 2 台の PC で同時に書き換えることは想定しない（同期の競合はクラウドストレージ側の仕組みに任せる）。

## 3. 保存先の切り替え（`set_db_path`）

| 操作 | 動作 |
|---|---|
| ファイル → 保存先を移動… | 保存先を選ぶ。そこにファイルが無ければ、今のデータベースと `covers\` をコピーしてから開く（同名の表紙ファイルは上書きしない）。ファイルがあれば、コピーせずにそれを開く。 |
| ファイル → データベースを開く… | 選んだファイルを開く（無ければ新しく作る）。 |

- 今と同じファイルを選んだらエラー。
- 開けたら `settings.json` に記録し、次回の起動でもそれを開く。
- 元のファイルは消さない。

## 4. 起動時

設定の保存先を開く。開けなければ（同期ドライブが未接続など）エラーを出力して既定のデータベースを開く。設定は書き換えないので、次の起動では再び設定の保存先を試す。

## 5. 自動バックアップ

データベースを開いたとき（起動時と保存先の切り替え時）に、全書籍を `books_backup.json` に書き出す（JSON 配列。各要素は `books` の 1 行）。書籍が 0 件のときは書き出さない（空や壊れたデータベースで、良いバックアップを上書きしないため）。

復元の手順はユーザーマニュアル §8 にある。
