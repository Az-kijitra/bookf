# Spec ID 台帳 (`bookf`)

仕様は領域ごとに管理する。Spec ID は `SPEC-<領域番号>-<連番>` 形式（例: `SPEC-0300-0001`）。

仕様と実装が食い違うときは、どちらが正しいかを決めてから両方をそろえる。仕様を変えたら、その仕様の「改訂履歴」と下の一覧の「最終更新」を更新する。

## 領域一覧

| 領域番号 | 領域名 | ディレクトリ | 説明 |
|---|---|---|---|
| 0100 | プロダクト方針 | `specs/product/` | 目的・基本コンセプト・スコープ |
| 0200 | アーキテクチャ・技術基盤 | `specs/architecture/` | 技術スタック、モジュール構成、フロントエンドとバックエンドの境界 |
| 0300 | 機能 | `specs/features/` | 画面とキー操作、データモデル、書誌情報の取得、保存先と同期 |
| 0400 | 品質・テスト | `specs/quality/` | テスト戦略、静的チェック |
| 0500 | ドキュメント | `specs/documentation/` | README・ユーザーマニュアル・変更履歴の整合 |
| 0600 | 配布・リリース | `specs/release/` | NSIS インストーラー、バージョン、リリース手順 |
| 0900 | ロードマップ | `specs/roadmap/` | 今回スコープ外の将来候補（要件ではない） |
